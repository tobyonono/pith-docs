## Our Stack

These are the tools we reach for — chosen deliberately, revisited regularly, and used because they've proven themselves in production across real projects. We're not married to any single tool, but we have strong opinions about why these ones work.

<CardGroup cols={3}>
  <Card title="Framework" icon="code">
    **Next.js (App Router)** and **React**

    Next.js gives us server rendering, optimised image handling, and a mature deployment story out of the box. The App Router aligns well with how we structure complex UIs. React remains the right component model for everything we build.
  </Card>
  <Card title="CMS" icon="database">
    **Sanity**, **WordPress**, **WooCommerce**

    Sanity for structured content and custom editorial experiences. WordPress for clients who need a familiar, widely-supported platform. WooCommerce for commerce requirements within the WordPress ecosystem.
  </Card>
  <Card title="Animation" icon="wand-magic-sparkles">
    **GSAP (GreenSock)**

    The industry standard for production-grade web animation. Reliable, performant, and capable of the kind of nuanced, physically-believable motion that makes interfaces feel crafted rather than built.
  </Card>
  <Card title="Styling" icon="palette">
    **Tailwind CSS**, **CSS Modules**

    Tailwind for speed and consistency — especially useful on component-heavy builds. CSS Modules for scoped, conflict-free styles when working closer to the metal. We choose based on project size and team context.
  </Card>
  <Card title="Language" icon="terminal">
    **TypeScript**

    TypeScript on every project by default. The upfront investment in types pays back quickly in fewer runtime errors, better editor support, and codebases that are easier to hand over and maintain.
  </Card>
  <Card title="Deployment" icon="rocket">
    **Vercel** (Next.js), **WP Engine** (WordPress)

    Vercel for Next.js deployments: fast global CDN, preview environments per branch, and zero-config CI/CD. WP Engine for managed WordPress hosting with strong performance, security, and staging workflows.
  </Card>
</CardGroup>

## Design Tools

**Figma** is our primary design environment — used for wireframes, high-fidelity mockups, prototyping, component documentation, and developer handoff. When we work with external design collaborators, Figma is the shared source of truth.

---

## Developer Tooling

Consistency in the development environment matters — it reduces friction, catches problems early, and keeps codebases clean as they grow.

| Tool | Purpose |
|------|---------|
| **VS Code** | Primary editor, with a shared extensions list for new projects |
| **ESLint** | Enforcing code quality rules across the project |
| **Prettier** | Automatic, opinionated code formatting — no style debates |
| **Husky** | Git hooks to run checks before commits land |
| **lint-staged** | Running linters only on staged files, keeping pre-commit hooks fast |

## Project Management

We adapt to what works best for each client and project:

- **Linear** — For engineering-heavy projects that benefit from issue tracking, sprints, and cycle-based planning.
- **Notion** — For projects that need a more flexible mix of documentation, task tracking, and client-facing updates in one place.

We'll recommend one at project kickoff based on team size and complexity, but we're comfortable in both.

## Communication Tools

- **Slack** — Async messaging for day-to-day questions, quick decisions, and keeping things out of email. Most projects get a dedicated channel.
- **Loom** — For async video walkthroughs. Far more efficient than writing long explanations for design reviews, staging feedback, or end-of-week updates. Record once, watch when ready.
